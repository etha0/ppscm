# SCM 사이트 개발 
  1. 상품등록 및 관리 
     - 상품을 카테고리로 관리한다. 이때 카테고리의 depth는 1개로 한다. 이때 상품코드는 관리자가 직접 입력하도록 한다 
       > 엑셀로 업로드 다운로드 할수 있도록 하는 기능 필요함 
     - 상품의 가격을 관리한다. 이때 발주하는 업체에 별도로 가격을 책정할수 있도록 한다.
      > 퍼센터지로 일괄 적용 및 직접 입력으로 수동입력을 둘다 쓸수 있도록 한다 
     - 상품의 이미지를 여러장 올릴수 있도록 하고, 발주사이트에는 대표 이미지를 썸네일로 목록에 보여주도록 한다 
  2. 입고 관리
     - 입고 관리는 관리자가 수기로 등록한다  
     - 상품이 입로되면 상품 입고를 등록하고 재고에 반영된다
     - 매일마다 관리자가 수기로 재고를 수정할수 있도록 한다.
       출고했을때 재고를 변경하게 될텐데, 오프라인에서 로스가 발생하거나 분실이 발생하면 재고를 수동으로 변경할수 있어야 한다 
  3. 수주 관리
      - 발주사이트를 통해 발주된 내역을 관리한다 
      - 발주사이트를 통해 각 매장의 관리자가 발주를 등록한다 
      - 이때 반품은 마이너스(-) 로 등록할수 있도록 한다 
      - 동일한 상품이라 할지라도 각 매장별 발주시 상품금액이 다를수 있다 
      - 이후 출고를 하게 될텐데, 출고가 되었는지 여부도 화면에서 확인할수 있어야 한다 
   4. 출고 관리
      - 발주된 목록에 대해서 출고를 진행할수 있도록 한다 
      - 출고 진행시 혹시 상품부족으로 인해 출고가 안된다면 해당 제품만 빼놓고 별도로 출고할수 있도록 한다 
        즉, 하나의 출고 마스터건에 대해서 출고가 여러건 붙을수 있다 
   5. 사아트 관리자 관리
      - 관리자 사이트에 접속 가능한 사용자 관리
   6. 매장 관리
      - 매장을 등록 수정 삭제할수 있는 페이지 
      - 매장에는 여러개의  아이디만 부여할수 있되, 발주 권한을 별도로 부여할수 있어야 한다 
   7. 사용자 관리
      - 관리자가 수동으로 사용자 등록하도록 한다 
      - 해당 사용자는 매장에 속한 사용자로 매핑한다. 이 사용자들은 발주사이트에 로그인 하기 위함이다
   8. 재고 관리      
     - 매일마다 관리자가 재고관리를 해서 수기로 재고를 수정할수 있도록 한다.
       출고했을때 재고를 변경하게 될텐데, 오프라인에서 로스가 발생하거나 분실이 발생하면 재고를 수동으로 변경할수 있어야 한다 
    
# ORM(발주) 사이트 개발
   1. 매장에 매핑된 사용자가 로그인 하면 해당 매장의 발주 내역을 조회, 및 발주 할수 있도록 한다 
   2. 발주 페이지
      - 상품을 발주하는 페이지
      - 여러건의 상품을 한번에 발주할수 있다. 이때 발주번호는 하나가 생성되며 각 발주번호 및에 세부번호가 순차적으로 생성된다 
      - 발주 취소를 할수 있다.
      - 발주 수정은 할수 없다. 아직 출고하지 않은 발주건에 대해서 취소만 가능하다

# 공통
   1. 입고, 출고, 발주 등의 페이지에는 통계 페이지 필요
      - 매장별, 날짜별, 상품별 조회할수 있도록 통계 페이지 필요
   2. 그리드 사용해서 사용자가 직관적으로 데이타 등록 및 관리 할수 있도록 필요, 이때 상용소스는 사용하지 말것
   3. 디자인은 밝고, 신뢰감 있고, 안정적인 느낌으로 페이지 만들어줘
   4. DB는 MariaDB로 개발해줘

   
# 화면 구현 기준 (2026-09-06)
- 서비스명은 **부조뱅크 SCM**으로 한다.
- 백엔드/프런트엔드를 별도 프로젝트로 구분하지 않고 전통적인 Servlet + JSP/JSTL 구조로 구현한다.
- 로그인부터 관리자 및 매장 발주 화면 전체에 밝고 신뢰감 있고 안정적인 디자인을 적용한다.
- 모바일에서는 메뉴를 접고 카드·폼을 재배치하며 넓은 표는 영역 내에서 가로 스크롤한다.
- 화면 목록, 실행 방법 및 현재 데모 범위는 [02.화면구현.md](02.화면구현.md)를 참조한다.

# 계정별 실제 기능 개발 (2026-09-06)
- SUPER / ADMIN / STORE_ORDER / STORE_VIEW 권한을 서버에서 검사한다.
- 매장 계정은 자기 매장의 가격과 발주만 조회하며 발주 가능 권한이 있는 계정만 등록/취소한다.
- MariaDB에 업무 데이터를 저장하고 발주 단가 스냅샷과 입출고 트랜잭션을 적용한다.
- 기존 거래 이력 보존을 위해 매장·계정·상품의 삭제 대신 중지 상태를 사용한다.
- 반품 등록 시 실제 재입고 여부를 선택한다. 출고가 시작된 발주는 취소할 수 없다.
- 실행 방법과 세부 업무 정책은 [02.화면구현.md](02.화면구현.md)를 참조한다.
